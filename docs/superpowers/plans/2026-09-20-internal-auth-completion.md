# 内网认证闭环补齐计划

## 目标

把公司内网 Docker 站点从“登录页可用”补成完整的登录闭环，同时不改变现有经营看板的数据和页面业务逻辑。

## 范围

1. 认证服务增加登录失败限流，避免账号被无限尝试。
2. 认证服务记录不含密码的登录成功、失败、登出和服务异常审计事件。
3. 运营看板侧增加当前登录用户、在线状态、注销入口和会话失效自动回登录页。
4. 未登录跳转保留原始安全站内路径，登录后回到原页面。
5. 保持 GitHub Pages 静态预览兼容：静态预览中认证控件隐藏，不影响原有看板。
6. 完成本地测试、Docker 测试和服务器部署后的真实登录/退出验证。

## 不做

- 不把认证配置、密码或密钥提交到 Git。
- 不把 GitHub Pages 改造成伪认证页面。
- 不改动现有运营数据模型、利润公式、导航业务模块和 Feishu 逻辑。
- 不在本次变更中引入数据库或外部认证服务。

## 验收标准

- 连续错误登录达到阈值后返回 429，等待窗口后恢复。
- 正确登录后看板显示当前账号，可点击注销；注销后业务页面跳回登录页。
- 会话过期或被清除后，前端自动跳回登录页并保留安全的原路径。
- 登录页、看板和受保护业务静态资源均可正常加载。
- GitHub Pages 首页仍返回 200，原有脚本无认证服务时报错阻断。
- 服务器两个容器 healthy，内网地址完成真实登录和注销验收。
